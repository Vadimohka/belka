# Belka — беларускамоўная LLM, обучаемая с нуля

Belka — исследовательский проект по созданию небольшой беларускамоўнай языковой модели
**с нуля**: курируемый корпус → собственный токенизатор → случайно инициализированная
nanochat/GPT-модель → базовый pretraining → беларускамоўный SFT → оценка language-lock.

> **Research preview.** Belka — это open-source проект кода и исследовательского пайплайна.
> Это не продакшн-модель. Исторический корпус опубликован в репозитории;
> расширенный корпус для H200 готовится локально и переносится отдельно с контрольными суммами.

## Миссия

Дать **воспроизводимый и проверяемый** путь к беларускамоўнай LLM — полезный
исследователям NLP, специалистам по low-resource языкам и всем, кто хочет воспроизвести
training/eval пайплайн для кириллического, морфологически богатого языка.

## Почему беларуский / low-resource

Беларуский язык слабо покрыт массовыми LLM: мало качественных открытых корпусов, две
орфографии (наркамаўка и тарашкевіца), сильная интерференция с русским. Belka решает это
инженерно (language-lock фильтрация, разметка орфографии, проверки пересечений с оценочными наборами).
**Предобученные мультиязычные модели используются только как eval-бейзлайны, не как
обучающая база.**

## Артефакты и текущий код — разные статусы

| Параметр | Значение |
|---|---|
| Корпус | Опубликованный `v3b`: по манифесту 302 991 train / 6 183 validation; прежнее «ПРИНЯТ» — исторический статус, не допуск нового запуска. |
| Токенизатор | собственный BPE, SHA256 `d9272e81…71ac` |
| Базовая модель | Исторический `belka-d8-base-v3-pilot`; не модель, переобученная после всех изменений PR №5. |
| SFT | Код генерирует проверяемую v9 из сохранённых v8 seeds; независимая языковая приёмка остаётся отдельной задачей. |
| Strict holdout | 209 промптов; прежний нулевой exact-overlap относится к полям конкретной проверки, не ко всем данным и видам утечек. |

Исторический отчёт: [`reports/public/PROJECT_STATUS.md`](reports/public/PROJECT_STATUS.md).
Текущий runtime получает BPB-длины из сырых байтов токенизатора; старые оценки,
использовавшие неправильный cache, нельзя сравнивать без пересчёта:
[пояснение](docs/TOKEN_BYTE_DERIVATION.md). Историческая оценка ~180,6M токенов
не является новым подсчётом training targets с BOS.

## Подготовка и запуск

Для готовых `source.tar` / `prepared.tar` используйте
[гайд SSH-сервера](docs/H200_TRAINING.md): требования, передача, установка,
оценка времени, `tmux`, запуск и resume. Для основного профиля рекомендуется
одна целая H200 141 ГБ, 16–32 vCPU, 128 ГБ RAM и 1 ТБ свободного NVMe.
Команды ниже относятся к повторной подготовке данных из исходников.

`ops/local/quickstart.sh` теперь готовит проверяемые данные и tokenizer без обучения.
Расширенный режим требует локальные файлы из `configs/h200_local_sources.json`;
`--curated-only` явно выбирает меньший опубликованный корпус. Старые поколения сохраняются.

```bash
bash ops/local/prepare_h200.sh --cpu --nanochat-dir .workspace/nanochat-h200
bash ops/local/run_belka_h200_maxquality.sh --help
```

Основной кандидат — 1,38 млрд параметров; варианты — 537 млн и 2,82 млрд.
Микробатч, память и оценка времени определяются реальным замером на H200.
[Полная инструкция, перенос на сервер и ограничения](docs/H200_TRAINING.md).

## Структура репозитория

```text
configs/        профили обучения, реестр источников, кандидаты на расширение, политики
data_pipeline/  нормализация / language-фильтр / dedup / split
tools/          инструменты: корпус, leakage, source-board, валидация
eval/           наборы language-lock / holdout / regression / refusal + runner
seed_sft/       сохранённые v8 seeds; v9 строится генератором в data_pipeline/
data_ready/     небольшие bundled bootstrap/seed/eval jsonl
docs/           методология: инвентарь данных, пайплайн, токенизатор, обучение, этика
data_cards/     карточки датасета (corpus_v3b)
model_cards/    карточки модели (belka-research-preview)
reports/public/ курируемые публичные отчёты
reports/state/  машиночитаемое каноническое состояние
release/        чек-лист и заметки релиза
ops/            опциональные owner/agent workflow-файлы (не нужны для базового чтения)
```

## Примечание о структуре репозитория

Основная research-preview поверхность — `README_RU.md`, `configs/`,
`data_pipeline/`, `eval/`, `tools/`, `tests/`, `reports/public/`,
`data_cards/` и `model_cards/`.

Опциональные owner/agent workflow-файлы вынесены в `ops/` для прозрачности,
но не нужны для базового чтения проекта.

## Ограничения

- Исторические размеры/оценки относятся к своим артефактам; качество новой конфигурации не измерено этим обзором.
- Наборы оценки небольшие; нет претензий на продакшн-качество.
- Орфографии размечаются, но не идеально разделены.
