# Checkpoint commit-manifest validation — R26-C01

Scope: validate `commit_<step>.json` before consulting tokenizer artifacts,
hashing checkpoint payloads or calling `torch.load`. This is issue #7 and a
bounded part of R26, not completion of trainer resume (R27).

## Reproduced defect

At parent `43233ba14d54b6746aa4b573738dc5fabfa7b208`, the checkpoint module
SHA256 was `3a6d58ffa136689c2ef6b941cb4361c79c8f838530f24fe1678853875781f0f7`.
On real temporary files, `validate_checkpoint(..., step=1)` accepted all seven
cases: a repeated `step` key, boolean step, boolean world size, zero world size,
NaN world size, null backend, and a commit-marker symlink. The fixture supplied
only the tokenizer identity lookup; real file hashing was used. No fixture
payload was deserialized during this reproduction.

## Accepted v1 contract

The commit marker must be a regular non-symlink file, at most 1 MiB. It is read
with a size bound before strict UTF-8/JSON decoding. Duplicate object keys at
any level, non-finite constants, invalid JSON and excessive JSON nesting fail.

Exactly these top-level fields are required:

- `schema`: `belka-checkpoint-v1`.
- `step`: a nonnegative integer (not boolean or float), equal to the requested step.
- `world_size`: a positive integer, not boolean or float.
- `backend`: a nonempty, non-whitespace string.
- `tokenizer`: a hash map containing `tokenizer.pkl`; `token_bytes.pt` is optional.
- `files`: a nonempty file-name-to-SHA256 map.

All hashes are 64 lowercase hexadecimal characters. Paths must be canonical
filenames for this step and a rank inside the saved world size. Model tensors
use `.pt`, metadata uses `.json`, and optimizer/RNG files use `.pt`. Model and
global metadata plus every rank's metadata and RNG must be listed, as produced
by the existing v1 writer. Optimizer files remain optional for inference-only
checkpoints; requesting optimizer resume still requires the local rank's
optimizer file. Impossibly large declared world sizes are rejected before a
rank loop is allocated from them.

Normal writer output is unchanged. More-than-six-digit steps are supported;
noncanonical filenames, unreviewed extra fields or renamed tokenizer artifacts
are not silently accepted as v1. Extensions need an explicit schema migration.
Existing world-size/backend/tokenizer-identity and all-payload hash checks remain.

A corrupt, directory, FIFO or dangling-symlink marker is an error, not permission
to fall back to legacy loading. When the marker is absent, the previous warning
and `BELKA_ALLOW_LEGACY_CHECKPOINT=YES` policy are retained. New-format partial
saves still cannot use that legacy override. No checkpoint is rewritten, deleted
or regenerated by validation.

## Tests

```bash
PYTHONPATH="$PWD" python -m pytest -q tests/test_checkpoint_manifest_schema.py
```

Expected with CPU PyTorch available: 85 passed. Without PyTorch, 83 source-only
cases pass and two serialization tests are explicitly skipped. The full Runtime
contracts workflow installs real pinned PyTorch, so these two cases must run
there. All temporary data are synthetic, and only tokenizer identity discovery
is replaced by a fixture. Existing runtime/Gloo tests provide adjacent coverage.

The tests cover valid writer layouts, malformed fields, duplicate keys, hashes,
file-name step/rank/extension mismatches, bounded reads, nonregular marker paths,
lookup indices, legacy policy, real CPU save/load, and refusal before tensor
loading. Final remote results belong to the GitHub issue and workflow artifacts,
not to an unverified hard-coded success claim here.

## Boundaries and rollback

Hashes establish integrity relative to the manifest, not origin/authenticity.
Only load trusted checkpoints; `weights_only=True` is not a general sandbox.
This preflight assumes the checkpoint directory is not being concurrently
modified by an adversary. It does not make payload hashing/deserialization one
race-free filesystem transaction, validate arbitrary trainer metadata, change
checkpoint discovery policy, prove GPU/NCCL behavior or prove full trainer resume.

Rollback this scoped commit rather than rewriting checkpoints. That restores the
older permissive validation; it must not be used to hide corrupt metadata.
