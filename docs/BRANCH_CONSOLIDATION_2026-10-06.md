# Объединение веток Belka — 6 октября 2026 года

## Результат и смысл операции

По явному запросу владельца рабочей веткой стала `main`; пять прежних
`codex/belka-*` веток удалены. Открытых PR после объединения не осталось.
Это изменение организации репозитория, **не заключение о готовности обучения**.
Задача #30 и описанные в TASKS.md ограничения не закрываются этим документом.

Актуальные рабочие файлы взяты из PR #5, head
`38a80d119e1bef77d2cee7deec8e49d50a2a8203`. PR объединён обычным merge-коммитом
`f47baf5f41ffe10b2c6557c37fc3e94d0523361d`: без squash, rebase и переписывания
опубликованной истории. До операции main указывал на
`d6cd920d32901e194e2bc0e0300186698a8d4c65`.

## Почему ранние альтернативы не наложены поверх текущего runtime

Четыре более ранние ветки расходились с PR #5 от общего предка. В них были
альтернативные версии checkpoint, SFT, installer, data contracts и временных
аудиторских workflows. Они не являлись простыми копиями последней ветки.
Механически смешивать эти реализации означало бы заменить или продублировать
уже доработанные компоненты и активировать непроверенные комбинации.

Поэтому их точные коммиты и полные исторические деревья сохранены как
дополнительные родители коммита
`07e422e6c41d7456b0e389599c9cf891f3af2298`. Его рабочее дерево **побайтово
совпадает** с результатом PR #5: Git tree
`a3091a0eca38e575d91c63c12e1886d41a961eb5`.

Это явно обозначенное объединение истории с сохранением текущего рабочего
дерева, а не заявление, что уникальные функции каждого старого PR портированы,
испытаны или включены в действующий runtime. Их исходники доступны по SHA и
остаются в достижимой истории main. Закрытие старых PR #2–#4 при таком объединении
не заменяет содержательную приёмку их альтернативного кода.

## Как проверено удаление

Одноразовый workflow **One-shot Git branch cleanup**, run
[37443870359](https://github.com/Vadimohka/belka/actions/runs/37443870359),
завершился успешно. Проверены его job log и итоговый список веток через API.
Служебная операция выполняла только Git/API housekeeping: без checkout проекта,
импорта его Python-модулей, установки зависимостей, тестов, чтения корпуса и обучения.

Для каждой ветки проверены точный ранее прочитанный SHA, отсутствие защиты
ветки и достижимость её вершины из main. Удаление выполнено одним атомарным
Git push с **отдельной exact-SHA lease для каждого удаляемого ref**. Новый коммит
в любой из выбранных веток привёл бы к отказу, а не к удалению этого коммита.
Имена веток перечислены явно; массовый wildcard-delete не использовался.
Ветка main не входила в набор удаления и не обновлялась принудительно.

Вместе с пятью ветками удалён временный триггер
`maintenance/branch-cleanup-2026-10-06`, указывавший на
`2f1f3c0e0abb4b8cdffae658ecd6812b5608b602`.
После выполнения одноразовый workflow удалён из текущего дерева тем же
документальным коммитом, который добавляет этот реестр. Он не оставлен как
постоянный автоматический очиститель будущих веток.

Обычные project CI/training workflows не запускались этой операцией: служебные
коммиты содержат `[skip ci]`. Успех Git housekeeping не является новым результатом
Runtime contracts и не приписывает main старые тестовые результаты как новые.

## Обновление локального checkout

При чистом рабочем дереве:

```bash
git status --short
git fetch origin --prune
git switch main
git pull --ff-only origin main
```

При локальных изменениях сначала сохраните их обычным способом; не используйте
`reset --hard`, `clean -fd` или принудительное удаление локальных веток ради pull.
Удаление удалённой ветки не требует уничтожать локальную копию её истории.
Обновление исходников Belka не переустанавливает nanochat overlay и не меняет
локальные данные автоматически.

## Восстановление исторического варианта

В полном checkout main прежний файл можно прочитать без запуска проекта:

```bash
git show 81c312e5075d1d6666410551cc7c5bb2cc2e7b65:ops/local/modernize_nanochat.py
```

При необходимости можно создать отдельную локальную ветку из любого SHA в
таблице. Не откатывайте для этого main и не смешивайте альтернативный runtime
со старым окружением без отдельной проверки совместимости.

## Что не изменилось

Рабочий runtime, обучающие скрипты, профили, upstream pin, зависимости и данные
остались версиями PR #5. Завершающий коммит меняет только README.md,
README_RU.md, TASKS.md, этот документ и удаляет одноразовый служебный workflow.
Большой технический патчноут остаётся датированным историческим срезом.

Неопубликованный локальный пакет подготовки #30 не появился в main от
объединения Git-историй. Известные проблемы старых launch-скриптов и требования
к локальному runtime/данным/оборудованию остаются предметом отдельной работы.
