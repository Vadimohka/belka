## Текущий маршрут: одна H200, до 7 суток

Реализованы `tools/training_plan.py` (plan/check/execute), безопасные generation-based
данные, train-only tokenizer и реальные token counts, аппаратный probe и полный SFT resume.
`quickstart` готовит данные; длительное обучение запускается отдельной командой.
[Практическая инструкция](docs/H200_TRAINING.md).

- [x] Единый read-only plan/check, безопасные owner entrypoints и профили одной H200.
- [x] Base/SFT exact resume с реальными CPU-тренерами и восстановлением interrupted saves.
- [x] Отдельная финальная очистка и проверки языка/дубликатов/holdout перед BPE.
- [x] Реальный HF reference export, честные INCOMPLETE/UNSUPPORTED в eval/deployment.
- [x] README/quickstart согласованы с новым маршрутом.
- [x] Фактический допущенный корпус: 3 274 476 train / 48 740 val документов;
  новый BPE32768 и полный подсчёт 1 635 285 758 / 17 977 093 токенов с BOS.
- [x] Заключительные 1545 тестов без пропусков; реальный CPU smoke 3 base + 3 SFT,
  неизменность завершённых checkpoints при resume и проверка provenance.
- [x] Проверка трёх планов на 168 часов и настоящее восстановление архива данных.
- [x] Требования SSH-сервера, явные расчётные сценарии времени и гайд переноса;
  удалено около 20,4 ГБ временных файлов с сохранением выбранных данных и checkpoints.
- [ ] Заключительная аппаратная приёмка на H200: память, BF16, throughput, диск, 168h budget.
- [ ] Production-обучение, strict holdout/GLUE и независимая языковая оценка результата.

Локальная проверка всех изменений и конкретные артефакты данных фиксируются в
`reports/audits/` и `reports/data/`. Статусы предыдущих CI ниже — историческая справка,
не замена нового отчёта. H200 будет подключена владельцем позже.

## Правила закрытия следующего этапа

Не закрывать общий предтренировочный этап только по числу прошедших тестов.
Нужны конкретный опубликованный коммит, полный отчёт выбранных данных,
отсутствие необъяснённых блокеров и отдельная owner-проверка оборудования/языка.
Не переписывать сохранённые config/hash значения ради продолжения обучения.
Не считать отсутствие GPU в CI успехом GPU-проверки. Не смешивать `warm start`
из base с восстановлением прерванного SFT. Не удалять старые checkpoints,
токенизаторы или поколения корпуса автоматически.

Для обучения использовать только принятые owner entrypoints с явным разрешением;
до публикации и приёмки #30 новые локальные черновики не являются таким путём.
